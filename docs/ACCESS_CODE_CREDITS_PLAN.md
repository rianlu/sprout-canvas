# 访问码与灵感点改造清单

更新日期: 2026-09-13. 状态: 原 80 项改造及后续异常结算, 无限额度, 管理交互, 前台用户浮窗, 可撤销润色和访问码操作简化已完成, 本机 Docker 已升级. 使用第 10 节核对异常结算, 第 11 节核对额度与界面调整, 第 12 节核对访问名称与近期画卷, 第 13 节核对润色与按钮展示, 第 14 节核对删除/重置与冲突刷新; 将真实模型效果, 真机兼容和容量压测继续按功能架构评估中的边界单独验收.

## 1. 固定产品规则

- [x] 将普通工作台登录改为访问码登录, 使用灵感点统一控制图片和文字处理额度.
- [x] 将多人共用同一码作为正常使用场景: 共享余额, 按各自浏览器隔离任务, 结果与操作权限.
- [x] 不设置访问码有效期. 通过余额和启用/停用状态管理使用权限; 保留正常的登录会话过期机制.
- [x] 默认每个图片任务消耗 10 点, 每个文字任务消耗 1 点; 允许管理员修改两项单价, 按正整数校验.
- [x] 将文生图, 参考图生成和蒙版编辑统一计为图片任务. 将提示词优化和分镜拆解计为文字任务.
- [x] 按计划提交的任务计次, 不按按钮点击次数, 下载次数或上游内部尝试次数累计扣点. 同一图片任务意外返回多张结果时仍按提交时的任务点值结算.
- [x] 让浏览风格, 复制模板, 查看和下载已有作品保持免费. 有限额度余额为零时允许登录与免费操作, 拒绝新增消耗灵感点的请求.
- [x] 不新增账号注册, 充值支付, 会员套餐, IP 历史统计, IP 绑定或设备指纹功能. 将匿名浏览器身份仅用于任务隔离与恢复.
- [x] 保持 Node + SQLite + Docker 和全局单图像 worker, 保持生成图片不在服务端持久保存的约定.

## 2. 访问码生成与登录

- [x] 由服务端使用安全随机数生成 `sc_` 加 32 个 Base64URL 随机字符, 使用 24 字节随机数据, 并在数据库中校验唯一性.
- [x] 让管理员填写用户可见的访问名称和初始灵感点, 支持单个创建与批量创建. 为每条访问码维护稳定内部 ID, 将点数与状态放在服务端.
- [x] 仅在创建或重置时返回完整访问码供复制保存. 数据库存储哈希与展示尾号, 不在 URL, 普通日志或公开配置中暴露完整码.
- [x] 保持访问码与上游 API Key 分离. 继续只在服务端使用 Provider 密钥.
- [x] 将登录输入名称改为访问码, 接受首尾空白清理, 校验长度和字符格式, 保留粘贴与正在登录状态.
- [x] 为访问码签发独立会话, 支持多人同时登录同一码. 不使用共享会话 token, 不因新登录挤掉其他浏览器.
- [x] 沿用请求大小限制, 同源校验和同一连接来源 10 分钟内 8 次错误尝试的限制. 限流计数保存在内存并自动过期, 不新增后台 IP 记录.
- [x] 展示格式错误, 无效/停用访问码, 请求过于频繁和网络失败等可操作反馈. 错误登录不扣灵感点, 不调用模型, 不自动停用访问码.
- [x] 停止使用原共享访问密码和免密码会话作为普通生成入口. 管理员继续独立登录后台, 进行创作时使用访问码.

## 3. 多人共享与浏览器隔离

- [x] 分开保存访问码的点数归属和浏览器的任务归属. 从服务端已验证的会话取得两者, 不将客户端自行提交的用户编号当作权限证明.
- [x] 按浏览器归属限制任务列表, 状态, 图片结果, 领取确认, 取消, 编辑, 置顶和参考链访问. 知道别人的任务 ID 也不得操作或领取.
- [x] 将同一访问码在所有浏览器中的点数预占和结算合并计算. 更换浏览器或清理本地存储不得重置该码余额.
- [x] 保留同一浏览器多标签页的任务恢复和幂等提交. 将本地图库继续保存在该浏览器中, 不将同一浏览器配置描述为多个独立账户.
- [x] 将退出, 重新登录, 更换访问码和重置访问码后的待提交请求正确关联到授权身份. 不把旧访问码的未完成操作静默转给新码扣点.
- [x] 保留全局串行图像队列和现有容量保护. 让多人等待队列时仍可看到各自状态, 共享余额同步更新.

## 4. 灵感点账本与结算

- [x] 在现有任务 SQLite 中增加访问码, 点值规则, 预占记录和点数流水. 将入队与额度预占放入同一事务, 防止只创建任务或只占用点数.
- [x] 使用整数处理点数并校验数值上限. 拒绝负可用余额, 数值溢出和管理员调整已被任务预占的点数.
- [x] 在服务端校验访问码状态, 请求参数, 通道能力, 队列容量, 点值版本和余额, 通过后才预占并受理任务.
- [x] 为每个请求保存点数快照和规则版本. 后台调价只影响新任务; 页面仍持有旧报价时要求刷新确认, 不静默按更高点值受理.
- [x] 在服务端成功取得可用结果时正式扣点, 不以浏览器下载或领取作为扣点条件. 已成功任务的删除, 刷新和临时结果过期不自动返还点数.
- [x] 对执行前取消, 校验失败和明确生成失败释放预占. 防止同一任务重复返还或重复结算.
- [x] 对已调用上游但超时, 中断或重启后结果未知的任务保留预占, 标记待核实. 允许管理员手动确认扣除或返还并填写原因, 不自动重复调用上游.
- [x] 将重复点击, 网络重试, 恢复排队和相同请求编号的再次提交识别为同一请求. 显式重新生成的新任务按新的请求编号与点值扣点.
- [x] 将文字请求也接入稳定请求编号, 内容校验, 预占, 结果复用和结算, 覆盖提示词优化与系列拆解. 同一次文字请求不得因响应丢失而再次调用或扣点.
- [x] 对单图多张和系列批次统一校验并预占整批点数. 余额不足时整批不受理; 断网后通过原请求编号查回已受理任务, 仅续交未受理内容.
- [x] 在批次受理后逐个结算任务, 支持部分成功, 单镜取消和失败返还. 保留首镜参考依赖及失败后的恢复流程.
- [x] 保留预占, 扣除, 返还和管理员调整的可追溯记录. 为管理操作防重复提交, 为明细查询提供分页.
- [x] 将访问码余额和账本生命周期与 7 天任务元信息清理分开. 清理历史任务不得重置余额, 也不得让原请求再次扣点或自动生成.
- [x] 验证数据库写入失败时不丢账, 不超额调用上游; 结算未完成时保持可核实状态, 不通过重新生成处理结算失败.

- [x] 保持独立后台地址和管理员权限. 不在用户端风格库或公共导航重新添加管理按钮.
- [x] 保留风格图片上传/拖拽/粘贴, 原文与作者录入, 分类/来源/排序, 上下架, 版本校验和完整备份恢复.
- [x] 为访问码列表展示访问名称, 尾号, 启用状态, 可用点数, 预占点数, 累计消耗和最近使用时间. 提供搜索与状态筛选.
- [x] 点击卡片打开统一管理弹窗, 支持创建, 批量创建, 修改访问名称, 有限/无限额度, 追加/扣减点数, 启用/停用, 重置与删除码. 对扣减, 停用, 重置和删除说明影响, 记录调整原因.
- [x] 为图片和文字提供两项点值设置, 保存时校验版本, 防止多页面编辑覆盖.
- [x] 在访问码详情中提供任务类型, 时间, 点数变化和状态等使用明细, 支持处理待核实预占.

- [x] 对已发往上游的任务正常收尾和结算, 为原浏览器保留受限的结果领取路径, 不因码停用/重置直接丢弃在途结果或自动重发.

## 10. 异常结算整改

- [x] 将图片与文字统一接入上游结果分类. 将 HTTP 408/504/524, 无明确完成信息的网关错误, 超时正文, 连接中断和截断响应保留为待核实, 不自动换通道或重发.
- [x] 区分 DNS/连接拒绝等明确未连接错误和已发送后的断流. 仅对确认未执行或明确失败的可重试请求切换通道, 最终只按原操作结算一次.
- [x] 识别 HTTP 200 中的错误对象, Responses 失败/未完整结束事件和已完成图片. 校验 JPEG 结束标记, 不把截断图片直接计为成功.
- [x] 将系列 JSON, 指定幕数和完整标题/提示词校验放在扣点之前. 无效结果返还预占, 有效结果与浏览器使用相同解析规则.
- [x] 保持多图逐张结算. 对首镜失败或结果未知返还未执行分镜, 对排队取消只返还一次, 对已执行请求拒绝取消.
